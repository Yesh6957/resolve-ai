🏗️ Technical Architecture (pipeline.py)

The demo above calls the real backend directly — this is the actual pipeline processing your input, not a client-side simulation:

  • Deterministic Safety Layer: Before hitting the LLM, regex patterns scan the text for PII (emails/phones), explicit toxicity, physical hardware damage, and billing keywords. This ensures escalation is guaranteed for obvious violations without depending on probabilistic LLM output.
  • LLM Intent Classification: A structured prompt requests the LLM (Codestral, via LLM7) to classify the tweet into one of 7 strict JSON categories (e.g., software_troubleshooting, billing_purchases), with the rule-based signals passed in as additional context.
  • ChromaDB RAG Retrieval: If the ticket is safe to auto-handle, the customer's text is embedded and queried against a local ChromaDB collection of historical Apple Support resolutions.
  • Grounded Generation: The LLM drafts a reply strictly grounded in the retrieved historical examples. If the ticket is escalated, no reply is generated at all — the ticket is routed straight to a human queue.

The "Misleading" Metrics

As requested in the assignment rubric, this section explores why the headline accuracy numbers hide the true performance of the system, and what specific failures occurred during the evaluation process.

🔍 Failure Analysis (Top 5 Modes)

  • LLM Domain Bias (Codestral): The model predicted software_troubleshooting 73 times for queries that were actually general_inquiry. Being a coding-centric model, its latent space over-indexes on software bugs.
  • Sarcasm Blindness: Customers tweeting heavy sarcasm (e.g., "I love being a beta tester for iOS") bypassed the rule-based toxicity checks and were auto-handled instead of escalated to human empathy teams.
  • Missing Temporal Context: Tweets complaining about "the letter 'I' glitch" failed because the LLM lacked the historical context of that specific 2017 iOS 11 bug.
  • Multi-Intent Ambiguity: "Updated my laptop and lost all passwords" triggered account_security, but the root cause is software_troubleshooting. Single-label classification forces false negatives.
  • Strict JSON Formatting Halts: Early in development, the LLM returned markdown fences (```json) which broke the parser until defensive cleaning steps were implemented in evaluate_3.py.

🎯 What I'd do with one more week

  • Model Swapping: Replace Codestral with a generalized, routing-specific model (like Claude 3 Haiku or Gemini 1.5 Flash) to immediately fix the software bias.
  • Dedicated Sentiment Triage: Run a fast Sentiment Analysis classifier *before* the intent classifier to strictly catch and escalate angry customers, fixing the low 24.21% escalation recall rate.
  • Dynamic Few-Shot Prompting: Programmatically inject 3 examples of the *hardest* classes (Billing, Security) into the prompt context to combat the Golden Dataset's heavy class imbalance.
  • Metadata Filtering in ChromaDB: Extract device types from tweets (e.g., "MacBook", "iPhone") and filter the vector search so Mac queries do not retrieve iPhone solutions.
